## 1. Performance
| ID | Area | Statement |
|---|---|---|
| NFR-001 | Response time | The system shall respond to at least 95% of API requests, excluding evidence-file uploads, within 3 seconds while supporting 1,000 concurrent users performing participant workflows. |
| NFR-002 | Response time | The system shall record an automated evidence-assessment result within 30 seconds for at least 95% of complete activity submissions, measured from successful receipt of all required evidence. |
| NFR-003 | Throughput | The web and mobile application shall display its largest visible content element within 2.5 seconds for at least 75% of page loads under the documented 4G network test profile. |

## 2. Security
| ID | Area | Statement |
|---|---|---|
| NFR-004 | Confidentiality | The system shall encrypt personally identifiable information, authentication tokens, and user-linked location data using AES-256 encryption. |
| NFR-005 | Confidentiality | The system shall protect personal data transmitted over network connections using TLS 1.2 or later. |
| NFR-006 | Confidentiality | The system shall store passwords exclusively as salted hashes generated by a secure password hashing algorithm. |
| NFR-007 | Confidentiality | Informed by survey privacy feedback and stakeholder interviews regarding location tracking, the system shall remove exact residential GPS coordinates from persistent storage immediately upon completing location validation. |
| NFR-008 | Confidentiality | The system shall remove EXIF metadata from uploaded evidence image copies before making those images accessible to other users or community feeds. |
| NFR-009 | Confidentiality | The system shall ensure that photographs of children, family members, or private home interiors are kept strictly private by default and excluded from public community feeds. |
| NFR-010 | Authentication | The system shall require multi-factor authentication (MFA) for all administrative accounts. |
| NFR-011 | Authentication | The system shall invalidate authenticated sessions after 15 consecutive minutes of user inactivity. |
| NFR-012 | Authorization | The system shall enforce role-based access control (RBAC) to ensure that only authorized administrative roles can access moderation panels and user management tools, and that corporate partners can view only data corresponding to their own sponsored activities and affiliated employees. |

## 3. Usability
| ID | Area | Statement |
|---|---|---|
| NFR-013 | Ease of use | The system shall allow an authenticated participant to complete either a manual or photo-upload activity submission in no more than four screen transitions, measured from the home screen to the submission-confirmation screen. |
| NFR-014 | Ease of use | Based on survey feedback and stakeholder interviews addressing volunteer barriers, at least 80% of first-time participants shall complete an activity submission without assistance within 2 minutes during usability testing. |
| NFR-015 | UI design | The system's participant-facing web and mobile interfaces shall conform to WCAG 2.1 Level AA accessibility requirements. |
| NFR-016 | Localization | The system shall display all participant-facing interface text in English or Arabic according to the participant's selected language preference. |
| NFR-017 | Localization | The system shall render all participant-facing interfaces in a right-to-left (RTL) layout when Arabic is selected. |

## 4. Reliability
| ID | Area | Statement |
|---|---|---|
| NFR-018 | Availability | The system shall achieve at least 99% availability per calendar month for core login, activity submission, and status retrieval features, excluding scheduled maintenance. |
| NFR-019 | Fault tolerance | The system shall store an activity submission as 'Pending Processing' when the automated AI assessment service or third-party mapping API is temporarily unavailable, supporting offline-first data capture during outdoor events where connectivity is limited. |
| NFR-020 | Fault tolerance | The system shall continue allowing participants to sign in and submit activities even when non-critical supporting features (such as leaderboards, social badges, or personalized recommendations) are offline. |
| NFR-021 | Disaster recovery | The system shall restore core service availability within 30 minutes of detecting an unexpected outage during recovery verification testing. |
| NFR-022 | Disaster recovery | The system shall limit the maximum loss of committed operational data to no more than 24 hours following a storage failure requiring backup restoration. |

## 5. Maintainability
| ID | Area | Statement |
|---|---|---|
| NFR-023 | Modifiability | The system shall permit the replacement of external service providers (such as AI verification or mapping APIs) by modifying only the corresponding integration module and configuration settings. |
| NFR-024 | Testability | Automated test suites shall achieve at least 80% branch code coverage for core business logic. |
| NFR-025 | Testability | Every permission rule defined in the system access-control matrix shall have automated unit tests covering both authorized and unauthorized access paths. |
| NFR-026 | Upgradability | The system backend shall support zero-downtime rolling updates or a rollback to the previous compatible release within 15 minutes during deployment verification. |

## 6. Scalability
| ID | Area | Statement |
|---|---|---|
| NFR-027 | Horizontal | Informed by survey and interview metrics targeting community campaigns, the system architecture shall support horizontal scaling to at least 1,000 concurrent active users by adding application instances without modifying source code. |
| NFR-028 | Vertical | The database and media server infrastructure shall scale vertically to accommodate increasing activity logs, corporate team records, and uploaded evidence volumes as the user base expands. |

## 7. Interoperability
| ID | Area | Statement |
|---|---|---|
| NFR-029 | Integration | The system shall integrate with recognized United Nations carbon accounting standards and frameworks (such as the GHG Protocol or standardized emission-factor databases) for calculating ecological metrics, ensuring impact figures are explicitly labeled as estimates. |
| NFR-030 | Data formats | The system backend shall communicate using standardized JSON data formats over RESTful APIs and support export of user personal data and corporate reports in standard machine-readable formats (JSON, CSV, or PDF). |

## 8. Compliance
| ID | Area | Statement |
|---|---|---|
| NFR-031 | Legal | The system shall comply with data protection regulations such as GDPR, providing users with mechanisms for data access, rectification, and complete account deletion (the right to be forgotten, including active data deletion and anonymization within 30 days). |
| NFR-032 | Legal | The system shall present clear, accessible data-processing notices and require explicit user consent agreements during initial user onboarding regarding personal information handling and corporate team sharing. |
| NFR-033 | Standards | The system shall adhere to secure coding and data management guidelines (such as OWASP Top 10 mitigation strategies) and incorporate compliance requirements for payment processing security where applicable. |

## 9. Capacity
| ID | Area | Statement |
|---|---|---|
| NFR-034 | Storage | The database and cloud file storage infrastructure shall support a minimum initial capacity of 500 GB of user-generated data (including verification photos and activity logs) and scale to accommodate active data growth for up to 10,000 registered users. |
| NFR-035 | Users | The system shall successfully process at least 99% of valid non-upload API requests with 1,000 concurrent users executing standard workloads. |
| NFR-036 | Users | The system shall durably acknowledge at least 99% of a batch of 250 activity submissions within 5 seconds when received simultaneously during peak community and corporate campaign events. |

## 10. Portability
| ID | Area | Statement |
|---|---|---|
| NFR-037 | Platform | The mobile application (built with Flutter) shall deploy and execute natively on Android and iOS devices. |
| NFR-038 | Cloud | The system backend (NestJS/Node.js) shall be containerized using Docker and be deployable across standard cloud provider environments (AWS, GCP, Azure). |
